## Aceites e evidências

- `/painel/ocorrencias` renderiza no servidor. Filtros de período UTC, status, prioridade, tipo e grupo autorizado ficam na URL. Atalhos do menu lateral, ordenação, paginação e reload preservam esses filtros. O formulário remonta quando a URL muda para refletir o estado corrente.
- Paginação padrão 1/50, máximo 100; sort somente createdAt/priority/status e direção asc/desc. ID asc desempata. SQL parametrizado aplica exclusão lógica e RLS. Total e página usam o snapshot de uma instrução SQL; somente a página limitada sai do banco.
- Fixture exclusiva da execução: 125 linhas do grupo A resultam em páginas 50/50/25; grupo B acrescenta oito somente para Gestor/Administrador autorizados. Quatro linhas de outro município e três excluídas não ampliam o conjunto operacional. Resultados dos filtros/sorts foram comparados a consulta SQL independente.
- Preferências persistem em `user_preferences`, próprias da conta verificada; não aceitam userId do cliente. A migration aditiva `202609300007_list_preferences` concede acesso somente à própria conta ativa, com whitelist de colunas também no SQL. Consulta não seleciona nem recebe nome/contato; rebaixamento de papel remove essas colunas efetivas imediatamente.
- API retorna 401 sem identidade, 403 sem acesso/grupo e 422 para filtros, sort, tamanho ou colunas inválidos. Parâmetros manipulados não são usados como autoridade. Navegadores verificam preferência restaurada, independência entre Operador e Consulta, vazio e erro recuperável.
- `/painel/tabela` redireciona filtros compatíveis, incluindo mapeamento de status antigos, para a lista Core. Original arquivado em `src/modules/legacy-occurrence-table.tsx`, com blob Git idêntico `50ab4d01d0e571ef64cff47b688cc5e99cf79547`. Espaços finais herdados foram preservados.
- Histórico de oito migrations foi reproduzido em schema vazio isolado, preservando o snapshot dos dados existentes. Testes de contexto transacional e pool sem identidade residual continuam aprovados.
