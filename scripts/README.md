# Comandos locais Core

`with-env.mjs` carrega somente `.env` na raiz, preserva variáveis já injetadas e resolve os executáveis instalados sem shell. Arquivos `.env.*` alternativos são recusados. Nenhum comando inicia migrations automaticamente. Node 24.14.0 foi verificado nesta implementação.

`npm run inventory:legacy` consulta apenas metadados em uma transação READ ONLY. Exige `TEST_DATABASE_URL` e uma lista JSON explícita em `TEST_DATABASE_ALLOWLIST`; não conecta ao banco de execução. A saída contém esquema, constraints, índices e extensões, sem registros de cidadãos ou URLs de credenciais. O inventário ainda precisa incluir confirmação de políticas, publicação, contagens e arquivos em alvo isolado antes da baseline.

`npm run inventory:legacy -- --write-evidence` inclui políticas/publicações e salva o resultado sanitizado em `docs/releases/core/testing/results/ticket-01-observed-inventory.json`. A ausência das tabelas legadas é indicada explicitamente; sucesso do comando não significa que há uma cópia legada disponível ou que a baseline está aprovada.

`npm run test:restore` executa a restauração real dos schemas `public` e `geoalerta_private` usando `pg_dump`/`pg_restore`, preservando políticas, funções e ACLs. Exige `RESTORE_SOURCE_URL`, `RESTORE_DATABASE_URL` (distintos e ambos em `TEST_DATABASE_ALLOWLIST`), `RESTORE_SOURCE_IS_SYNTHETIC=true`, origem sintética confirmada, destino vazio e ambos diferentes do banco operacional. O comando nunca limpa o destino; se houver tabelas, interrompe. `RESTORE_REPORT_PATH` deve apontar para arquivo ainda inexistente. O relatório compara contagens, hashes e objetos do esquema sem expor credenciais ou valores das linhas. Auth, bytes do Storage, papéis globais e publicação Realtime exigem procedimentos próprios de recuperação. O modo Docker autorizado usa ferramentas PostgreSQL em imagem PostGIS validada, exclusivamente para alvos locais. Não execute no projeto Supabase compartilhado. A restauração final de 30 migrations/27 tabelas foi aprovada em 01/10/2026.

`prepare-legacy.ts` reproduz a fonte histórica autorizada pelo usuário somente em alvo de teste vazio; não reaplica criação em cópia existente. Em Docker PostgreSQL puro, usa pré-requisitos SQL sintéticos de plataforma explicitamente declarados. A baseline foi criada após observar esse esquema reproduzido. Prisma 7.10.0 CLI, client e adapter têm versões alinhadas.

Verificação: `npm run test:unit`, `npm run test:db`, `node scripts/with-env.mjs playwright test --list`.

Em 01/10/2026, Cassiano autorizou Docker como alternativa para esta adequação de banco e os tickets 19/20, substituindo a restrição anterior para esta execução. Isso permite testes PostgreSQL/PostGIS e restauração reais em bancos de containers descartáveis. As fixtures SQL de plataforma e o servidor Auth simulado continuam sem comprovar Auth, Storage ou Realtime reais; o aceite completo do ticket 20 requer esses serviços em homologação ou uma stack Supabase local completa. Não remover os guardrails do teste de carga para executá-lo no projeto compartilhado.

`npm run test:load` mede uma hora de carga com 100 criações, rajada inicial de dez, dez sessões, idempotência, atualizações, conflito, CSV completo e foto privada. A entrega de alertas usa o mesmo histórico autorizado consultado periodicamente pelo painel, em conjunto com WebSocket. `socketAlertsReceived` conta eventos recebidos pelo socket; `alertsRecovered` conta aqueles cuja primeira entrega ocorreu pela recuperação, podendo haver chegada posterior pelo socket. A latência `alert.endToEnd` considera a primeira entrega e os dois contadores não são somados. A [carga final de 01/10/2026](../docs/releases/core/testing/results/ticket-20-2026-10-01.md) passou com serviços oficiais Supabase em Docker, sem executar carga no projeto remoto.
